# contacts-lpr — скилл для Claude: сбор базы контактов и ЛПР

Скилл для Claude Code, который собирает **проверяемую базу компаний и лиц, принимающих решения**,
по открытым источникам — под любую нишу.

Не «накидать ссылок», а: снять бриф → найти компании → углубиться по каждой → собрать все контакты
с ролями и источниками → отранжировать так, чтобы первая строка была лучшим входом на ЛПР.

## Что он делает

1. **Бриф — пять вопросов, не анкета.** Что продаём · кого и где ищем · **что компания должна делать,
   чтобы стать клиентом, и кто НЕ подходит при том же профиле** · объём и срок · формат выдачи.
   Остальное (размер, статус, стоп-лист, приоритет ЛПР) скилл предлагает сам разумными значениями
   и просит поправить одной строкой. Итог — карточка ICP на подтверждение.
2. **Длинный список компаний.** Пять заходов: по рубрике (карты и каталоги), по коду (реестры ОКВЭД),
   по деньгам (госзакупки и B2B), по росту (вакансии), по соседям (конкуренты эталонных клиентов,
   их клиенты и поставщики). Журнал источников ведётся с первой минуты, гейт по заходам не даёт
   молча пропустить срез рынка. Дедупликация по ИНН, отбраковка, подтверждение списка пользователем.
3. **Глубокий проход по компании — 7 шагов тремя группами.**
   **Ядро** (реестры · сайт · каталоги) даёт сам контакт, **именные** (закупки · HR) дают ФИО
   контактного лица, **подъём** (соцсети и медиа · достройка контакта) выводит на личный контакт ЛПР.
   Внутри шагов пункты помечены «обязательно» и «если есть бюджет», есть правило, когда компания
   считается закрытой, и потолок запросов на компанию.
4. **Ранжирование.** Ступени 1–6 по качеству найденного входа на ЛПР, тир A/B/C. Без выдуманных баллов:
   ступень описывает то, что физически найдено, поэтому одинаково работает в любой отрасли.
5. **Выдача.** Markdown, CSV, XLSX (скрипт в комплекте), Google Sheets, импорт в CRM.
   Перед выдачей — чек-лист самопроверки из 12 пунктов.

## Что делает его пригодным для длинной работы

Сбор на несколько десятков компаний не помещается в одну сессию, поэтому в скилле есть:

- **`research.json` — накопитель.** Заводится первым действием Фазы 2 и пополняется после каждой
  закрытой компании. Из него собирается любой формат выдачи; он же — точка восстановления.
- **Работа пачками по 10** с отчётом после каждой и явной остановкой, когда контекст на исходе.
- **Протокол продолжения после обрыва:** прочитать JSON и журнал, сверить со списком, продолжить
  с нужной компании — без повторного брифа и пересборки списка.
- **Карта «как достаётся»** по каждому источнику: чем берётся, что делать при 403, капче, скролле.
  Правило двух подходов — дальше фиксируем «источник недоступен» и идём вперёд.

## Что проверено боем (правила из разбора реальных прогонов)

- **Профиль — по действию, а не по названию товара.** Компания подходит, если *делает* нужную работу,
  а не просто *упоминает* нужный продукт (список марок приводит и любой магазин). Исполнителя от
  посредника («оформим под ключ за N дней») скилл различает по доказательствам — цех, фото своих работ.
- **Проверка данных перед записью.** ИНН — по контрольной сумме (ловит демо-реквизиты и опечатки),
  карточка в реестре открывается по ИНН как по ключу (не по названию), телефоны — по белому списку кодов.
- **Реестр по ОКВЭД видит не весь рынок:** только юрлица, без ИП (в мелком бизнесе — половина рынка)
  и без подкодов; его результат обязательно дополняется картами и поиском.
- **«Не подтверждено» и «источник не открылся» — разные вердикты:** первое в отсев, второе на второй проход.
- **Формат выдачи утверждается на образце** (2–3 строки-примера), а не описывается словами.
- **Параллельные агенты — только с явного согласия пользователя:** скилл предлагает, объясняет,
  какие агенты куда пойдут, и предупреждает о кратном расходе токенов; не согласовал — работа идёт
  последовательно, без доп. агентов.

## Правовая рамка

Отдельный раздел в `SKILL.md`, и он сильнее задачи. Только открытые источники и только законными
способами: никакого подбора паролей и чужих учёток, входа в закрытые разделы, обхода авторизации
и капчи, поиска уязвимостей, слитых баз и «пробива» (ст. 272–274 УК РФ). Запрещено выдавать себя
за другого ради получения контакта. Персональные данные — только в рабочей роли и только
опубликованные для деловой связи (152-ФЗ, ст. 137 УК); коммерческая тайна и внутренние документы
не берутся, даже если оказались в открытом доступе (ст. 183 УК). Найденная утечка не используется.
Для рассылки — предупреждение про 38-ФЗ. Ответственность за использование базы несёт пользователь.

## Установка

**Claude Code (CLI, VS Code, JetBrains)**

```bash
# для всех проектов
git clone https://github.com/KsenNau/contacts-lpr.git ~/.claude/skills/contacts-lpr-repo
cp -r ~/.claude/skills/contacts-lpr-repo/contacts-lpr ~/.claude/skills/

# или только для одного проекта
cp -r contacts-lpr <ваш-проект>/.claude/skills/
```

Перезапустите Claude Code. Вызов: `/contacts-lpr` или фразой «собери базу контактов по …».

**claude.ai** — упакуйте папку `contacts-lpr` в zip и загрузите в Settings → Capabilities → Skills.

**Любой другой ассистент** — скормите содержимое `contacts-lpr/SKILL.md` и справочников как инструкцию.

## Структура

| Файл | Назначение |
|---|---|
| `contacts-lpr/SKILL.md` | Ядро: когда скилл не применяется, правовая рамка, 5 фаз, протокол длинной работы, ранжирование, чек-лист самопроверки |
| `contacts-lpr/references/interview.md` | Банк вопросов брифа |
| `contacts-lpr/references/longlist.md` | Фаза 1: пять заходов, дедупликация, отбраковка, расширение критериев |
| `contacts-lpr/references/sources.md` | Карта источников + поисковые операторы |
| `contacts-lpr/references/output-formats.md` | Форматы выдачи, JSON-схема, правила выгрузки в CRM |
| `contacts-lpr/scripts/make_xlsx.py` | Сборка XLSX из собранного JSON (`pip install openpyxl`) |

Разделение не случайно: ядро грузится всегда, справочники — только когда дошло до соответствующего шага.

## Принципы, зашитые в скилл

- **Не выдумывать.** Нет данных — «не найдено». Выведенная по паттерну почта помечается как гипотеза.
- **Каждый факт — со ссылкой на источник.** Факт без URL в таблицу не попадает.
- **Только открытые источники.** Никаких слитых баз, «пробива», агрегаторов чужих личных контактов,
  домашних адресов, персональных данных вне бизнес-контекста.
- **Ничего не пишется в CRM** без предпросмотра «будет создано N записей» и явного подтверждения.

## Правовая рамка

Скилл работает с тем, что компания опубликовала сама, или с тем, что публично по закону
(ЕГРЮЛ, госзакупки, арбитраж). Персональные данные — в рамках 152-ФЗ, только в бизнес-контексте.

Для холодного касания рекламного характера формально требуется согласие (38-ФЗ):
персональное деловое письмо конкретному ЛПР безопаснее массовой рассылки. Ответственность
за использование собранных данных — на пользователе.

Источники ориентированы на российский рынок (ЕГРЮЛ, ФНС, zakupki.gov.ru, hh.ru, 2GIS);
логика фаз универсальна — под другой рынок меняется только `references/sources.md`.
