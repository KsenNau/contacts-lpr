# Форматы выдачи

Сбор всегда ведётся в **промежуточный JSON** (`research.json` в рабочей папке) — из него собирается любой формат.
Не собирай сразу «красивую таблицу»: потеряешь источники и не сможешь пересобрать в другой формат.

**Файл заводится ПЕРВЫМ действием Фазы 2**, до первой компании, и пополняется после каждой закрытой
компании — не в конце работы (см. `SKILL.md`, «Первое действие фазы»). Он же служит точкой
восстановления, если сессия оборвалась.

**Сортировка обязательна во всех форматах.** Компании — по `step` (ступень 1 → 6, первая строка =
самый качественный вход на ЛПР), контакты внутри компании — по `priority` (1 = лучший).
Ничего не выбрасываем: слабые записи уходят вниз списка, а не в отдельный файл.
Ступени и правила порядка внутри ступени — в `SKILL.md`, раздел «Ранжирование выдачи».

Поле `rank` необязательное: если модель уже выстроила итоговый порядок с учётом критериев внутри ступени
(подтверждённость, ICP, свежесть повода), проставь `rank` целым числом от 1 — скрипт выгрузки
будет сортировать по нему, а `step` останется для наглядности.

## 1. Markdown-таблица (в чат или файлом в Vault)

**Сначала проверь, есть ли Vault вообще.** Признаки: рабочая папка — хранилище Obsidian,
есть `CLAUDE.md` и `00_Memory/current-session.md`. Если их нет — Vault-раздел ниже не применяется:
сохрани файл в рабочую папку сессии, отдай таблицу в ответе и скажи, куда положил файл.
Не выдумывай путь `40_Projects/...` и не подставляй `dir/` наугад — поля, которых неоткуда взять,
просто не пиши.

Если файл в Vault — обязательна шапка по CLAUDE.md:

```yaml
---
title: "База контактов — <ниша>, <гео>"
type: type/заметка
dir:  dir/<из current-session.md>
status: status/draft
owner: owner/Наумушкина-Ксения
updated: YYYY-MM-DD
tags: [type/заметка, dir/<...>, status/draft, owner/Наумушкина-Ксения]
---
```

Дальше: сводка → таблица «Компании» → таблица «Контакты» → список «не найдено».
Имя файла по правилам Vault: `YYYY-MM-DD-база-контактов-<ниша>.md`.

Широкие таблицы в Markdown нечитаемы — если колонок больше 8, делай короткую таблицу
(Ступень / Тир / Компания / Лучший контакт / Канал / Повод / Confidence), отсортированную по ступени,
а полное досье выноси карточками под ней в том же порядке.

## 2. CSV

Разделитель `;`, кодировка **UTF-8 с BOM** — иначе Excel на Windows покажет кракозябры.
Два файла: `companies.csv` и `contacts.csv`, связка по колонке ИНН.

## 3. XLSX

`python scripts/make_xlsx.py research.json out.xlsx` — два листа, автоширина, заморозка шапки,
цветовая пометка confidence. Требует `openpyxl` (`pip install openpyxl`).

## 4. Google Sheets / Drive

Через коннектор Google Drive, если он подключён в сессии: создать файл, отдать ссылку.
Если коннектор не подключён — сказать прямо и отдать CSV/XLSX локально, не изображать выгрузку.

## 5. Битрикс24

Порядок жёсткий:
1. Спроси портал, сущность (лиды или компании + контакты), воронку/стадию, ответственного, источник.
2. Проверь дубли по ИНН/телефону **до** записи (`crm.duplicate.findbycomm`, поиск по ИНН).
3. Покажи предпросмотр: «будет создано N компаний и M контактов, обновлено K» — с тем же самым
   набором параметров, который пойдёт в запуск (не пересобирать параметры между предпросмотром и записью).
4. Жди явного подтверждения. Только потом пиши.
5. После записи — отчёт: создано/обновлено/пропущено с ID.

Правило: контакты с `confidence: гипотеза` в CRM класть в комментарий, а не в поле телефона/почты,
иначе менеджер отправит письмо на несуществующий адрес и словит бан домена.
